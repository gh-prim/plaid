# F006 — Plan: Playback, direct play and transcoding

> This plan must be precise enough for the other dev to execute it alone.
> If the implementation diverges, this file is updated **in the same commit**.

**Starting point (checked 2026-10-27, `main` at `08be201`):**
- **HTTP:** `httpserver.New` mounts the strict oapi-codegen handlers on a `ServeMux` under `/api/v1`, wrapped as recover → access log → `clientinfo` → `auth.Authenticate`. The access log writes `r.URL.Path` as is. Streaming responses (`scan_events.go`, `images.go`) implement the generated response interfaces; none of them handle `Range` or need the `*http.Request`.
- **Auth:** `auth.Authenticate` allows `publicRoutes` (kept equal to the `security: []` operations by `public_routes_test.go`) and otherwise looks the session up **in the database on every request** (`accounts.Lookup`); there's no session cache and no revocation hook. `auth.NewToken` / `HashToken` / `EqualSecret` exist. `auth.IsLocal` covers loopback and `IsPrivate` (RFC 1918, RFC 4193), not link-local and not `100.64.0.0/10`.
- **Profiles and age limits:** `accounts.AccessLimit(ctx, principal)` returns `access.Limit`; `library.Item.AgeRating` is filled from `item_metadata` (F005).
- **Library:** `Store.GetItem`, `Store.ItemFiles(itemID)` return files with streams (`idx`, codec, language, channels, flags, `External` as a bool only). `probe_json` is stored but only parsed for Dolby Vision. `ProbeResult.Stream` has profile, width, height, frame rate, bit depth, HDR, channels, layout, but no `level` and no external subtitle path.
- **Settings:** `internal/settings.Store` (string get/set/delete) over the `settings` table from `0004_metadata.sql`.
- **FFmpeg:** `library.FindFFprobe` (`PLAID_FFPROBE_PATH`, else `PATH`); nothing finds `ffmpeg` yet. CI's server job installs the distro `ffmpeg` (Ubuntu 24.04, cached).
- **Packaging:** `postinstall.sh` **already** adds `plaid` to `video` and `render` when those groups exist; the unit keeps devices visible; `MemoryDenyWriteExecute=true`. `test-deb.sh` runs 24 checks including "hardening exposure below 2.0" and a library probed by the hardened service. Docker: trixie-slim + `ffmpeg`, compose has no device section. Releases are Linux only.
- **Migrations:** `0001`–`0004`; `db_test.go` has an incremental-upgrade test pattern.

**Other dev:** the `in-progress` plans (F001, F004, F005) are all owned by gh-prim, and F005's four PRs are merged. Nobody else is expected in these files, but F006 touches shared ones: `api/openapi.yaml`, `apierr.go`, `handlers/items.go`, `config.go`, `main.go`, `docs/install.md`, `CLAUDE.md`. Rebase before each PR; generated files are regenerated, never merged by hand.

**Delivery: three PRs**, each releasable on its own, since every merge to `main` ships:
- **PR A — sessions, Direct Play, watch state** (steps 1–11). Ends phase 1's goal for compatible files: sign in with `curl`, start a session, play the link in VLC. Sessions needing HLS answer `503 ffmpeg_missing` until PR B (the code path exists; FFmpeg isn't wired yet).
- **PR B — HLS: Direct Stream and software Transcode** (steps 12–23). Keyframe index, FFmpeg runner, playlists, seeking, subtitles, storage, limits, `PATCH`, settings routes.
- **PR C — hardware, HDR, admin, packaging, proofs** (steps 24–31). Hardware detection and fallback, tone mapping, admin "now playing", capabilities, artwork via token, Docker/`.deb` docs and checks, performance runs.

### PR B — HLS: Direct Stream and software Transcode
12. [x] **Test media.** `testmedia_test.go` builds clips once per run in a shared temp dir with `ffmpeg -f lavfi -i testsrc2 -f lavfi -i sine`: 60 s H.264/AAC MP4; 60 s H.264/AC-3 MKV with an embedded SRT and an ASS; 60 s HEVC Main10 MKV with HDR10 metadata (`libx265`, skipped if the encoder is missing); 30 s H.264 MKV with a `dvdsub` track (image subtitles; FFmpeg can't write PGS); 30 s MPEG-TS (no index); a 20-minute 360p H.264 MKV for seeking. All under 30 MB together.
13. [x] **Keyframe index.** Matroska: EBML reader for `SeekHead` → `Cues`, collecting `CueTime` of video `CueTrackPositions` (times scaled by `TimestampScale`), reading with `ReadAt` only the header, the SeekHead and the Cues element. MP4: `moov/trak` of the video track, `stss` sample numbers mapped to times through `stts` and the media timescale (`mdhd`), plus the edit list offset. Fragmented MP4 and anything else → no index. Cached in `media_keyframes`, invalidated when `mtime` changes. Tests on the generated clips (compared with `ffprobe -skip_frame nokey -show_frames`), a truncated file, a file with no Cues (a copy of the MKV clip whose `Cues` element is overwritten in the test by an EBML `Void` element of the same size), and a counter proving the reader never reads more than header + index. `Media.HasKeyframeIndex` is now filled. (R13)
14. [x] **Segments and playlists.** Transcode: `ceil(duration / 6 s)` segments, segment N starts at `N × 6 s`. Direct stream: group keyframes greedily into ~6 s, never under 2 s (merge into the previous one) or over 10 s (split only at keyframes; a > 10 s GOP stays as one segment). Playlists: master (one variant with `BANDWIDTH`, `RESOLUTION`, `CODECS` from the decision, audio group, subtitle group), media (VOD, `EXT-X-MAP:URI="init.mp4"`, `EXT-X-TARGETDURATION` = max segment rounded up), subtitle (one VTT segment for the whole duration). Golden tests on the playlists. (R11–R13, R16)
15. [x] **Command builder.** Argument lists (never a shell string) for: direct stream with video copy and audio copy or AAC; transcode in software (`libx264`, `-preset` from `encoderPreset`: `veryfast`/`faster`/`medium`), scaling, forced keyframes `expr:gte(t,n_forced*6)`, burn-in of image subtitles (`overlay`) and text subtitles (`subtitles` filter with the file path escaped for the filter syntax), audio downmix (`-ac 2`). Output: `-f hls -hls_segment_type fmp4 -hls_time 6 -hls_playlist_type vod -start_number N -hls_flags temp_file -hls_fmp4_init_filename init.mp4`. A run started at segment N must produce timestamps that start at N's time: `-ss <start>` before `-i` with either `-copyts -avoid_negative_ts disabled` or `-output_ts_offset <start>`. The step 16 spike picks one; the builder starts with `-copyts` and the goldens are updated if the spike says otherwise. Golden tests per case, including a file name with `'`, `:` and `,` for the `subtitles` filter. (R12, R17, R19–R21)
16. [x] **Runner and the timestamp spike.** **Do this first in PR B, before steps 13–15 are polished.** One run = one FFmpeg process in its session folder, `Setpgid` (+ `Pdeathsig = SIGKILL` on Linux), `-progress pipe:1` parsed for `out_time` and `speed`, stderr in a 64 KiB ring. A segment is ready when `N.m4s` exists and FFmpeg has moved past it (the temp-file rename, or segment N+1 started, or the run ended). Spike test: start at segment 0, then restart at segment 100 of the 20-minute clip; `ffprobe` segments 99 (from run 1) and 100 (from run 2) concatenated behind the same `init.mp4`: presentation times must be continuous (± 1 frame) and the init segments byte-identical for the same decision. If byte identity fails, the plan changes to serving one `init.mp4` per run with `EXT-X-DISCONTINUITY` on restarts, and this file is updated. Stop = `SIGCONT` (a throttled run ignores `SIGTERM` while stopped), then `SIGTERM` to the group, `SIGKILL` after 5 s, always `Wait`. **`Pdeathsig` trap:** Linux sends it when the *thread* that forked the child exits, and Go moves goroutines between threads. Every FFmpeg is therefore started by one spawner goroutine that calls `runtime.LockOSThread` and never returns (requests go to it over a channel); step 23 proves it. (R12, R14, R28)
17. [x] **Seeking and throttling.** Segment request logic per R14: ready → serve; produced within 3 segments → wait (20 s max, then `503 segment_not_ready` + `Retry-After: 1`); otherwise restart at N. Concurrent waits on the same run share one wakeup (`sync.Cond` or a channel per segment). Throttle per R15 with `SIGSTOP`/`SIGCONT` on the process group. Idle stop after 60 s without a segment request (R28). Tests with the 20-minute clip: jump to 15:00 first; seek back to before the first kept segment; 10 parallel requests of the same not-ready segment start FFmpeg once; a paused run resumes on request. (R14, R15, R28)
18. [x] **Storage.** `PLAID_TRANSCODE_DIR` emptied at startup (only PLAID-made session folders, matched by name, never anything else). After each segment request, segments more than 5 minutes behind are deleted. Global cap from `settings.transcodeDirMaxBytes` (default from `statfs`: `min(10 GiB, max(1 GiB, 20 % of free))`, computed at startup and logged); over it, oldest-behind segments go first across sessions, then new transcodes are refused with `503 transcode_storage_full`. Subtitle and keyframe caches in `$PLAID_DATA_DIR/cache/playback/`, 1 GiB LRU. Tests with a fake `statfs` and tiny caps. (R27)
19. [x] **Subtitles.** `GET /stream/{token}/subtitles/{index}.vtt`: embedded text streams with `ffmpeg -map 0:s:<n> -f webvtt`, external `.srt`/`.ass`/`.vtt` files converted the same way; cached by `(file id, mtime, stream index)`. `.ass` passthrough for embedded (`-c:s copy -f ass`) and external files. Index validated against the session's file. Tests: VTT timings of the SRT and ASS clips, the forced French external file, an index of another file → `404`. (R16)
20. [x] **Transcode slots and settings.** `maxTranscodes` default: hardware active → 4; else `NumCPU ≤ 4` → 1, otherwise 2. Only video re-encodes take a slot. A slot stays with its session across runs and short pauses, so pressing Play after a pause doesn't fail; it's released after 10 minutes without any activity (no progress report, no segment request). Resuming after that needs a free slot again, or the session answers `503 transcode_limit_reached` on its next segment and the client shows the message. `GET`/`PATCH /settings/playback` (admin) with validation (`localNetworks` as CIDRs, `remoteMaxBitrate ≥ 0`, `maxTranscodes` 1–32). Tests: the limit case from the acceptance criteria, an audio-only conversion not counted. (R26, R30)
21. [x] **Wire HLS into sessions.** The start handler now builds HLS sessions; `PATCH /playback/{id}` re-decides. If the decision is unchanged, nothing restarts and the response is the same `url`. Otherwise the current run stops, the session gets a new token (so a new `url`, and the old one answers `404` at once, which keeps cached segments of the old quality from mixing in) and a new folder, and the next run starts at `positionMs`. Responses include subtitle URLs. Logs per R39 with the command line (token-free by construction: tokens never reach FFmpeg). (R5, R6, R11, R39)
22. [x] **E2E, PR B.** Acceptance criteria that don't need hardware: decision cases end to end, Direct Stream seek to 1:42:00-equivalent (15:00 on the long clip) within the target, 6 s transcode segments, VTT rendition in the master playlist, `.ts` → `keyframe_index_missing`, FFmpeg gone 70 s after the client stops and 6 s after `DELETE`, limit `503`, storage cap. An HLS client helper in the test fetches master → media → segments and pipes `init.mp4` + segments into `ffprobe` to check duration and stream codecs.
23. [x] **Crash cleanup test (Linux).** The test binary re-executes itself as a child (`TestMain` helper mode) that starts a transcode, then the parent `SIGKILL`s it and checks with `/proc` that no `ffmpeg` with the session folder in its arguments remains after 2 s. Then a new service on the same folder empties it at start. Skipped on macOS (no `Pdeathsig`; documented). (R28)

### PR C — hardware, HDR, admin, packaging, proofs

## Risks
| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Timestamps or init segments differ between FFmpeg runs after a seek, so players stall or jump | High | Spike first (step 16) with an automated continuity check; fallback design (per-run init + `EXT-X-DISCONTINUITY`) written down in the step |
| Direct Stream segments misaligned with real keyframes (wrong Cues, edit lists, B-frame offsets), giving segments that don't start on a keyframe | Medium | Keyframe reader tested against `ffprobe` on generated files; any segment whose first packet isn't a keyframe in the e2e helper fails the test; unknown layouts → no index → transcode |
| FFmpeg processes leak (crash, panic, client gone) | Medium | Process groups, `Pdeathsig` from a locked spawner thread, `SIGCONT` before `SIGTERM`, idle stop, startup purge, the step 23 crash test, the `test-deb` "no ffmpeg after stop" check |
| Distro FFmpeg missing a filter or encoder on a target (`zscale`, `libvpl`) | Medium | Capabilities listed at start (`-filters`, `-encoders`); each feature degrades with a warning instead of failing; ADR 0006 revisited only with that data |
| `MemoryDenyWriteExecute` breaks a VAAPI driver under the hardened unit | Medium | Manual VAAPI test under the `.deb` unit in step 31; documented drop-in; the hardware probe turns the failure into a software fallback, never a broken playback |
| CI time grows with media generation and transcodes | Medium | Clips generated once per test run, small resolutions except the targeted cases, total under 30 MB; heavy cases in `-tags perf` only |
| SQLite write pressure from progress reports with many sessions | Low | One write per 10 s per session (R32); no writes on segment requests |
| `/stream` mounted outside the strict handlers drifts from the contract | Low | Operations still in `openapi.yaml`; handler tests assert status codes and content types per operation; `public_routes_test` keeps auth in sync |
| Shared files edited by F005 follow-ups (`items.go`, `openapi.yaml`) | Low | Rebase before each PR; regenerate code; F005's age-limit tests must stay green |

**Riskiest step:** step 16 (runner and restart-at-segment timing). Everything in PR B depends on restarted runs producing segments that a player can stitch to earlier ones. It's scheduled first in PR B with an automated check and a written fallback.

## Rejected options
- **Stream routes in the strict generated handlers** (with the `*http.Request` smuggled through the context for `Range`): fights the generator for `Range`, `HEAD`, `If-Range` and long-polling. Instead the routes stay in the contract and codegen skips the `stream` tag; a plain handler uses `http.ServeContent`.
- **Revocation hooks in `accounts`** (callback on every revoke path): logout, password change, admin revoke, disable and delete each revoke differently, and a missed path would leave a live stream. `SessionActive` checks on playlist and file requests, plus the 30 s reaper, cover every path with one query.
- **Using FFmpeg's own HLS playlist** (event playlist growing as segments are written): seeking past the produced part would wait for the encode. PLAID writes the full VOD playlist itself (R11) and FFmpeg's playlist is only a progress signal.
- **MPEG-TS segments:** no HEVC passthrough for Apple players and no AV1; fMP4 works for every target (hls.js, Safari, AVPlayer, ExoPlayer).
- **A Go HLS or FFmpeg wrapper library:** playlists are a few lines of text, and the hard part (process lifecycle, timing) is ours either way. No new dependency in F006.
- **Persisting playback sessions in SQLite:** the spec ends them on restart (R8) and FFmpeg runs can't survive one; memory is simpler and faster.
- **Full packet scan when a file has no index:** rejected in the spec (watch-out "keyframe index"): those files are transcoded.
- **`SupplementaryGroups=render video` in the unit:** the unit fails to start where a group is missing (containers, minimal installs). `postinstall.sh` already adds the groups that exist.
- **Transcode slots per FFmpeg run, or kept until the session ends:** per run, a slot freed by the 60 s idle stop of a short pause could be taken, and pressing Play would fail. Until the session ends, a paused tab blocks a Pi's only slot for up to 24 h. Middle ground in step 20: 10 minutes without activity.

The edit list is **forced**: on "auto", a run from 0 writes one and a restarted run doesn't, so their init segments differ; with `use_editlist=0`, the MP4 muxer shifts video later than audio by the B-frame delay (2 frames with x264). Forced, the inits are byte-identical, and a restarted segment starts on its time within half a frame, audio included (`TestRestartContinuity`, which also covers a B-frame MP4). `-force_key_frames expr:gte(t,n_forced*6)` counts from the run's start, which is always a segment boundary.
- **2026-10-27, step 16:** FFmpeg's HLS muxer cuts at the first keyframe at least `hls_time × k` after the run's start, so with a copied video its cut points depend on where the run started. Direct Stream runs therefore use `-hls_time 0.001`, writing one piece per source keyframe numbered by keyframe index, and PLAID serves segment N as the concatenation of its keyframe group's pieces (an fMP4 segment can hold several `moof`/`mdat` pairs). Transcode runs write one piece per 6 s segment. A Direct Stream run seeks to its keyframe + 1 ms, so millisecond rounding never lands on the previous keyframe.
- **2026-10-27, step 16:** with `temp_file`, FFmpeg writes `N.m4s.tmp` and renames it, so a piece that exists is complete. The init segment isn't written that way (0 bytes until the first piece), so each run writes `init-<run>.mp4`, and the first complete one is renamed to the session's `init.mp4`.
