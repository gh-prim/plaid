# F001 — Spec: Monorepo foundations

## Summary
Lay down the plumbing every later feature builds on: a Go server that serves an OpenAPI-defined API and an embedded React web app, generated clients, i18n from day one, a single `make` entry point, per-folder CI, and two ways to install the server: a Docker image, or a native Ubuntu/Debian package with a systemd service (the way people install Plex). Functionally the product does almost nothing yet: you open the browser, see a warm "your server is up" page in your language, and the page got that status from the API through the generated client. Everything after F001 is "add a feature", never "set up a tool".

## User journeys

**Dev, first clone**
1. Clones the repo, runs `make setup` (installs web deps and Go tools).
2. Runs `make dev`: the Go server starts on `:32500`, the Vite dev server on `:5173` and proxies `/api` to Go. Edits to either side hot-reload or restart.
3. Runs `make test`: Go tests, web tests, lint, i18n check and codegen drift check all run; the exit code says pass/fail.

**Dev, changing the API**
1. Edits `api/openapi.yaml`.
2. Runs `make generate`: Go server interfaces and TS client are regenerated.
3. The compiler points at every handler or call site that no longer matches.

**Self-hoster, first run**
1. Runs `docker compose up` (or the binary directly).
2. Opens `http://<host>:32500`.
3. Sees the PLAID welcome page: name, server version, status "up", in their browser's language (en or fr), with a language switcher.

**Self-hoster, native Ubuntu install (no Docker)**
1. Downloads `plaid_<version>_amd64.deb` (or `arm64`) from the GitHub release, or runs the one-line install script.
2. `sudo apt install ./plaid_<version>_amd64.deb`: creates the `plaid` system user, `/var/lib/plaid`, `/etc/plaid/plaid.env`, installs and starts `plaid.service`.
3. Opens `http://<host>:32500`. After a reboot the server is back on its own.
4. Upgrades by installing a newer `.deb`: the service restarts, data and config are kept.
5. `sudo apt remove plaid` keeps data and config; `sudo apt purge plaid` removes config (data in `/var/lib/plaid` is kept unless the user deletes it, to never lose a library by accident).

## Design

### Repo layout
```
plaid/
├── Makefile
├── docker-compose.yml
├── Dockerfile
├── .github/workflows/{server.yml,web.yml,docker.yml}
├── api/
│   ├── openapi.yaml
│   └── events.md
├── server/
│   ├── go.mod                      # github.com/gh-prim/plaid/server
│   ├── cmd/plaid/main.go           # wiring, config, signals
│   ├── internal/api/               # oapi-codegen output (generated, do not edit)
│   ├── internal/handlers/          # implements api.StrictServerInterface
│   ├── internal/config/
│   ├── internal/db/                # sqlite open + migrations/ (R16)
│   ├── internal/httpserver/        # mux, middleware (logging, recover), SPA handler
│   └── internal/webui/             # go:embed of the built web app
├── web/
│   ├── package.json, vite.config.ts, tsconfig.json, eslint.config.js
│   ├── src/api/schema.d.ts         # generated, do not edit
│   ├── src/api/client.ts
│   ├── src/i18n.ts
│   ├── src/locales/{en,fr}/common.json
│   └── src/pages/Welcome.tsx
├── design/tokens.json              # (R19)
├── .goreleaser.yaml                # binaries + .deb (R21)
└── packaging/
    ├── systemd/plaid.service       # (R23)
    ├── plaid.env                   # default config, installed to /etc/plaid/ (R22)
    ├── deb/{postinstall,preremove,postremove}.sh
    └── install.sh                  # one-line installer (R24)
```
Web build output is copied into `server/internal/webui/dist/` by `make build` (not committed; a placeholder `index.html` is committed so `go build` works without a web build).

### Data model
None functional. With R16: a `schema_migrations` table managed by the migration runner, nothing else.

### API
| Method | Route | Description |
|--------|-------|-------------|
| GET | `/api/v1/health` | Liveness + build info. No auth. |

```json
// 200 OK
{
  "status": "ok",
  "version": "0.1.0-dev",
  "commit": "02ec07a",
  "uptimeSeconds": 42,
  "database": "ok"
}
```
Errors on all `/api` routes use one shape, defined now so every later feature reuses it:
```json
{ "error": { "code": "not_found", "message": "Human-readable, in English" } }
```
`code` is a stable machine key; clients translate it through i18n, never display `message` to end users.

### Behavior per app
- **server**: as above. Serves API + embedded web on one port.
- **web**: welcome page only.
- **apple / android**: out of scope (phases 4 and 5). The OpenAPI spec is written so Swift/Kotlin generation will work later (no exotic constructs, explicit `operationId`s).

### UI / Art direction
One page, deliberately plain until F002 lands: centered PLAID wordmark (text), status line, version, language switcher. No design tokens yet; minimal inline CSS with a dark background so it doesn't flash white.

States:
- loading: "Warming up the couch…"
- ok: "Your server is up. Grab the blanket."
- error: "Can't reach the server. Is it still plugged in?"

## Non-functional requirements
- **Footprint**: idle RSS < 40 MB and cold start < 1 s on a Raspberry Pi 4 (arm64). Binary < 40 MB.
- **Toolchain**: Go 1.26 (pinned in `go.mod`), Node 24 LTS (pinned in `.nvmrc`), versions of codegen tools pinned (Go `tool` directive, npm lockfile).
- **CI time**: each job < 5 min on a cache hit.
- **Security**: runtime container runs as non-root; no secrets in the image; the only endpoint is unauthenticated health and it leaks nothing beyond version/commit.
- **Accessibility**: the welcome page has a proper `lang` attribute that follows the selected language.

## ⚠️ Watch-outs
All settled by gh-prim on 2026-10-26. ✅ = resolved, ⏸ = tracked elsewhere.

- [x] **Default port** — ✅ `32500`.
- [x] **Web package manager** — ✅ pnpm (most mature lockfile and CI caching story; bun's Vite/ESLint compatibility is less proven).
- [x] **License** — ⏸ Deferred. Must be decided (short ADR, AGPL vs MIT) before the repo goes public and before any image is published.
- [x] **SQLite in F001 (R16)** — ✅ Included. F003 and F004 run in parallel and both need a database; bootstrapping it once here avoids two competing DB layers.
- [x] **Runtime base image** — ✅ Debian slim (not distroless), so F006 can add FFmpeg and GPU drivers without changing base.
- [x] **Binding to `0.0.0.0` with no auth** — ⏸ Harmless with only `/health`. Tracked in F003: it must land before any endpoint that exposes data.
- [x] **ghcr.io publishing (R18)** — ⏸ The workflow is written, but publishing stays disabled until the license is decided.
- [x] **Media folder permissions (native install)** — ✅ The `plaid` user can't read `/home/you/Films` by default (the #1 Plex-on-Linux support issue). F001 documents the fix (add `plaid` to the media's group, or ACLs); F007's folder picker will detect and explain unreadable folders.
- [x] **FFmpeg for the native package** — ⏸ Tracked in F006 (distro `ffmpeg` vs our own build, as Jellyfin does). F001 declares no FFmpeg dependency.
- [x] **APT repository (R25)** — ⏸ Later (needs hosting and a GPG key). Until then, upgrade = install the new `.deb` or re-run the script.
- [x] **Install script trust (R24)** — ✅ Short, readable script that verifies checksums; the manual `.deb` download is documented for cautious users.

## Acceptance criteria
- [ ] Given a fresh clone with Go, Node and pnpm installed, when I run `make setup && make test`, then it exits 0.
- [ ] Given `make dev` is running, when I open `http://localhost:5173`, then I see the welcome page with status "ok" and the dev version, fetched through the generated client.
- [ ] Given the server is running, when I `curl /api/v1/health`, then I get `200` and a JSON body matching the schema in `openapi.yaml`.
- [ ] Given the server is running, when I request `/library/123` (non-API path), then I get the web app's `index.html`; when I request `/api/v1/nope`, then I get a JSON `404` with `error.code = "not_found"`.
- [ ] Given my browser is set to French, when I open the page, then the text is in French and `<html lang="fr">`; when I switch to English, then it updates without reload and stays English after a reload.
- [ ] Given I add `<p>Hello</p>` to a component, when I run `make lint`, then it fails on a hard-coded string.
- [ ] Given I add a key to `en/common.json` but not to `fr/common.json`, when I run `make test`, then it fails and names the missing key.
- [ ] Given I edit `openapi.yaml` without running `make generate`, when CI runs, then the drift check fails.
- [ ] Given a PR that only touches `web/`, when CI runs, then the Go job does not run (and vice versa).
- [ ] Given `docker compose up`, when I open `http://localhost:32500`, then I see the welcome page, and the process inside the container is not root.
- [ ] Given the server receives SIGTERM during a request, then the request completes and the process exits 0.
- [ ] Given a fresh Ubuntu 24.04 VM without Docker, when I `sudo apt install ./plaid_<version>_amd64.deb`, then `systemctl status plaid` is active, `http://<vm>:32500` shows the welcome page, and the process runs as `plaid`.
- [ ] Given the native install, when I reboot the machine, then PLAID is reachable again without any manual action.
- [ ] Given I edited `/etc/plaid/plaid.env` (e.g. changed the port), when I install a newer `.deb`, then my edit is kept and the service runs the new version.
- [ ] Given the native install, when I `sudo apt remove plaid`, then the service is stopped and `/var/lib/plaid` still exists.
- [ ] Given an arm64 machine (e.g. Raspberry Pi with Ubuntu), when I run the install script, then it picks the `arm64` package, verifies its checksum and installs it.
- [ ] (R16) Given an empty data dir, when the server starts, then `plaid.db` is created in WAL mode and health reports `"database": "ok"`.
